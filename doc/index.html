01 / How it works

Follow the administrative path.

Start with all provinces. Each result includes an id. Send that ID to the next endpoint to get its children. Continue until you reach the villages inside a cell.

Province→District→Sector→Cell→Village

Important: use the public URL below in your application. The local URL in the README is only for running the project on your computer.

02 / Endpoints

Choose the data you need.

03 / Responses

Predictable JSON output.

Collection endpoints return a data array and a count. Child records also show parent_id, so your application can keep the relationship clear. 

{
  "data": [
    { "id": 1, "name": "East" },
    { "id": 2, "name": "Kigali" }
  ],
  "count": 5
}

For example, the tested public path is East (province 1) → Bugesera (district 1) → Gashora (sector 1) → Biryogo (cell 1).

04 / Contact messages

Send JSON with POST.

The homepage contact form uses this endpoint. Your app can use it too. A name, valid email, and message are required; the message is saved in the MySQL contact_messages table. 

fetch("https://rwanda.rf.gd/api/contact.php", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    name: "Jane Doe",
    email: "jane@example.com",
    message: "Hello from my application"
  })
});
Successful output / HTTP 201{ "message": "Thank you. Your message has been received." }

05 / Errors

Clear feedback when something is wrong.

When a request fails, the API returns JSON with an appropriate HTTP status code: 

{ "error": { "message": "A positive integer province_id is required." } }
200 Successful request201 Contact created400 Invalid input404 Endpoint not found503 Database unavailable
